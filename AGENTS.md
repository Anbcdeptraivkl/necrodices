# NecroDices (working title "Rattle & Roll") — Agent Guide

Halloween 2026 dice-summoning roguelike: roll elemental dice, bind them into monster groups,
score `Power × Count` Balatro-style against human monster-hunters. Godot 4.6.3, GDScript,
landscape 480×270 pixel art, Web desktop first (itch.io), mobile landscape second.

This file is the entry point for every AI agent working here. `CLAUDE.md` imports it.

| Read | For |
| --- | --- |
| [GAME_SPEC.md](GAME_SPEC.md) | Rules, algorithms, content tables, milestones — **normative** |
| [ART_SPEC.md](ART_SPEC.md) | Resolution, palette, sprites, UI rects, asset manifest — **normative** |
| [docs/IMPLEMENTATION_PLAN.md](docs/IMPLEMENTATION_PLAN.md) | Build order, task breakdown, progress — read at the start of work, update when a task finishes |
| [DECISIONS.md](DECISIONS.md) | Every ambiguity resolved and every deviation from the specs, with the why |
| [docs/tech.md](docs/tech.md) | Engine version, commands, folder layout, how to run / test |

Never rename IDs defined in GAME_SPEC §6. Content lives in `data/*.json`; code never
hard-codes stats, prices or HP.

## Skill protocol (mandatory)

Skills are reusable, project-agnostic know-how. They live in
`.claude/skills/<name>/SKILL.md`; the index below lists every one. Project-specific facts
(paths, numbers, decisions) live in the specs and `docs/`, never in a skill.

**1. Select, before any work.** For every task other than a pure question, read the index
and pick every skill whose *Use when* matches the task — the files it touches, the system it
changes, or the kind of work (design, implement, debug, test, review). When in doubt,
include it.

**2. Load, then plan.** Load each selected skill in full (the `Skill` tool, or read its
`SKILL.md`) *before* planning or editing. Open only the `references/` files a skill routes
you to for the sub-task at hand.

**3. Declare.** Start the plan or first reply with one line:
`Skills: <name>, <name>` — or `Skills: none — <why no entry matches>`.

**4. Order of authority.** User instruction in the conversation > this file > GAME_SPEC /
ART_SPEC / DECISIONS > `docs/` > a skill. When a skill conflicts with a higher source, follow
the higher one and say so.

**5. Close the loop.** Before finishing, ask: did this task teach something reusable (a trap,
a pattern, a missing or wrong rule)? If yes, update the owning skill in the same change
(`skill-maintenance`). Never let a skill silently disagree with what the code does.

**6. Keep the index honest.** After adding, renaming, editing a description of, or deleting
a skill, run `python tools/skills_index.py --write`. Without a flag it validates; a
session-start hook runs it.

## Git and commits (mandatory)

- Never commit or push on your own initiative. Commit only when the user asks for a commit in
  the current conversation; push only when the user asks for a push. One approval covers one
  operation. "Implement / fix / proceed" authorizes working-tree changes and tests only.
- Same for amend, rebase, reset, merge, branch switch/delete, tag, stash, force-push.
- Never bypass hooks (`--no-verify`); fix the cause.
- **Commit message rule** (enforced by `.githooks/commit-msg`; overrides any tool default):
  - exactly **one line**, short and readable (≤ 72 characters, aim for ~50);
  - starts with a **capital letter** and an imperative verb: `Add`, `Fix`, `Update`, `Remove`…;
  - says *what changed*, not how: `Add scorer with spec fixtures`, `Fix shop reroll cost reset`;
  - **no body, no trailers**: no `Co-Authored-By`, no "Generated with", no ticket noise.
  Pass it as `git commit -m "<line>"` only — never a heredoc or second `-m`.

## Working rules

- Build in the milestone order of GAME_SPEC §13 / the implementation plan; a milestone's
  acceptance criteria pass before the next starts.
- `core/` is pure logic (`RefCounted`, no `Node`, no scene access) and is unit-tested headless.
  Presentation plays back the ScoreTrace; it never computes rules.
- When the spec is ambiguous, choose the option closest to Balatro's behaviour and log it in
  `DECISIONS.md` (ID, date, decision, why).
- Art: `python tools/gen_placeholders.py` only creates missing files; it overwrites only ids
  named with `--only` or with `--force`, and only on the user's request. Modified art files in
  the working tree are the designer's work — never revert, regenerate or "clean" them.
- Before handing over: `python tools/check_data.py`, `python tools/validate_art.py`,
  `tools\test.cmd`.
